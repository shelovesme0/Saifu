# Резервна копія Saifu

Функція поза лабораторними: експорт і імпорт усіх даних у JSON та автоматична копія в папку, яку обрав користувач. Працює без нових capabilities і без платного акаунта розробника: папку вибирає системний Document Picker (`.fileImporter`), доступ до неї зберігається як security-scoped bookmark, а на iOS це не потребує entitlements.

## Де зберігати копії

Контейнер застосунку, зокрема папка «Файли → На iPhone → Saifu», видаляється разом із застосунком, а з ним і копії. Тому:

- папку всередині контейнера не можна вибрати для автокопії. З'являється повідомлення «Ця папка видаляється разом із застосунком. Оберіть iCloud Drive або іншу папку»;
- якщо вручну експортувати копію в контейнер, файл зберігається, але з'являється попередження з тією ж порадою;
- у секції «Резервна копія» завжди видно підпис «Зберігайте копії в iCloud Drive, щоб вони пережили видалення застосунку».

Перевірку робить `AppContainer.contains(_:)` (`Saifu/Backup/BackupFolder.swift`): шлях вибраної папки чи файлу має починатися з домашньої директорії застосунку (`NSHomeDirectory()`). Перед порівнянням шлях нормалізується: розгортаються символьні посилання й `..`, прибирається завершальний `/`, а `/private/var/...` (так шлях повертає пікер) прирівнюється до `/var/...` (так виглядає домашня директорія). Сусідня папка з таким самим початком імені (`…/A2` для `…/A`) не вважається вкладеною.

Копія перед імпортом (`Saifu-before-import-…`) без обраної папки автокопії пишеться в Documents застосунку, тобто теж у контейнер. Вона потрібна, щоб скасувати невдалий імпорт, поки застосунок встановлений. Щоб зберегти її надовго, перенесіть файл в iCloud Drive.

## Що потрапляє в копію

Усі гаманці в поточному порядку, кожен з витратами, поповненнями та останньою звіркою. Налаштування (домашня валюта, нагадування) лишаються в `UserDefaults` і в копію не входять.

## Формат файлу (версія 1)

```json
{
  "appVersion" : "1.0 (1)",
  "createdAt" : "2026-11-24T09:05:12.481Z",
  "formatVersion" : 1,
  "wallets" : [
    {
      "currency" : "jpy",
      "expenses" : [
        {
          "amount" : 580,
          "category" : "smallShop",
          "date" : "2026-11-24T08:41:03.112Z",
          "id" : "4F09E482-5CB8-42AC-A39F-E9AE47716F52",
          "note" : "7-Eleven"
        }
      ],
      "id" : "0C1D6F0E-2B8A-4C47-9B0E-7E2C1B1F9A10",
      "lastReconciliation" : {
        "actual" : 18500,
        "date" : "2026-11-24T08:50:00.000Z",
        "expected" : 18470
      },
      "name" : "Японія",
      "topUps" : [
        {
          "amount" : 20000,
          "date" : "2026-11-24T08:00:00.000Z",
          "id" : "A3B1C2D4-1111-4222-8333-944455556666",
          "source" : "atm"
        }
      ]
    }
  ]
}
```

- **Суми** — `Int` у найменших одиницях валюти гаманця (єни, копійки, центи), як і в моделях.
- **Enum-и** — `rawValue`: `currency` (`jpy`, `uah`, `eur`, `usd`), `category` (`food`, `groceries`, `smallShop`, `transport`, `household`, `leisure`, `untracked`), `source` (`atm`, `correction`).
- **Дати** — ISO 8601 в UTC з мілісекундами. Дата округлюється до мілісекунди і при записі, і при читанні, тому повторний експорт відновлених даних дає той самий файл.
- **Порядок гаманців** — порядок масиву `wallets`. Записи всередині гаманця впорядковані за датою.
- `note`, `receiptID`, `lastReconciliation` необов'язкові.

Формат описують окремі Codable-DTO (`Saifu/Backup/BackupDTO.swift`), а не доменні моделі. Модель можна змінювати, не ламаючи старі файли: несумісна зміна формату означає нове значення `formatVersion` і окреме читання старої версії.

## Імпорт і перевірка

1. Спершу читається лише `formatVersion`. Якщо це не JSON або поля немає, з'являється повідомлення «Файл пошкоджений або не є резервною копією Saifu». Невідома версія дає «Копію створено новішою версією застосунку (формат N)».
2. Потім файл розбирається повністю й перевіряється: відомі валюта, категорія й джерело поповнення, суми > 0, фактична сума звірки ≥ 0, коректні дати, унікальні id гаманців і записів.
3. Лише після успішної перевірки з'являється підтвердження «Поточні дані буде замінено. Перед цим буде збережено їхню копію».
4. Після «Замінити» поточні дані зберігаються у `Saifu-before-import-YYYY-MM-DD-HHmm.json`: у папку автокопії, якщо вона обрана й доступна, інакше в Documents застосунку («Файли → На iPhone → Saifu»). Якщо цю копію записати не вдалося, імпорт скасовується.
5. `WalletRepository.replaceAll(with:)` замінює всі дані однією транзакцією SwiftData. Якщо запис не вдався, контекст відкочується, і в пам'яті та на диску лишаються попередні дані.
6. Екрани оновлюються: репозиторій `@Observable`, тому головна, аналітика й список гаманців перераховуються самі. Відкриті екрани й sheet закриваються (`AppRouter.resetNavigation()`), а форми додавання витрат створюються наново, бо тримали старі екземпляри `CashWallet`.

На кроках 1–4 поточні дані не змінюються.

## Автоматична копія

- **Увімкнення.** Налаштування → «Резервна копія» → «Автоматична резервна копія». Тумблер відкриває вибір папки; рекомендовано папку в iCloud Drive. Папку всередині контейнера застосунку відхилено (див. «Де зберігати копії»), і тоді тумблер вимикається, якщо робочої папки ще не було. Після вибору одразу записуються `Saifu-latest.json` і сьогоднішній знімок: так перевіряється, що в папку можна писати. Якщо закрити пікер без вибору, тумблер повертається у вимкнений стан.
- **Файли в папці.**
  - `Saifu-latest.json` — актуальна копія, перезаписується після кожної зміни даних.
  - `Saifu-backup-YYYY-MM-DD.json` — щоденний знімок, не частіше одного на день: його створює перший запис дня. Лишаються 7 найновіших знімків, старіші видаляються.
- **Коли пишеться.** Після кожної зміни: витрата, поповнення, редагування, видалення, звірка, створення чи зміна гаманця, порядок гаманців, імпорт.
  - **Звідки відомо про зміну.** Усі зміни проходять через `WalletRepository`. Декоратор `ChangeNotifyingWalletRepository` після кожного успішного `save` / `remove` / `move` / `replaceAll` викликає `BackupViewModel.dataChanged()`. ViewModel екранів про автокопію не знають.
  - **Дебаунс ~3 с.** Кожна зміна переносить запис на 3 с від себе, тож серія змін (кілька витрат поспіль) дає один запис.
  - **Лише справжні зміни.** Перед записом SHA-256 від JSON гаманців (без дати створення файлу) порівнюється з відбитком останньої автокопії. Якщо дані не змінилися, нічого не пишеться.
  - **Вихід у фон.** Якщо є незаписані зміни (дебаунс ще не спрацював), запис іде одразу, всередині фонового завдання (`beginBackgroundTask`), щоб iOS не призупинила застосунок посередині. Якщо саме йде запис, фонове завдання чекає на нього.
- **Як пишеться.** JSON готується на головному акторі (там живуть дані, це мілісекунди), а файлові операції виконуються у фоновому `Task.detached`, тож UI не блокується. Записи йдуть строго по черзі. `Data.write(options: .atomic)` спершу пише тимчасовий файл, потім підміняє: обірваний запис не псує попередню копію.
- **Що не чіпається.** Ротація стосується лише імен `Saifu-backup-` + `YYYY-MM-DD` + `.json`. Ручні експорти (`Saifu-backup-YYYY-MM-DD-HHmm.json`), `Saifu-before-import-…`, `Saifu-latest.json` і файли інших застосунків лишаються.
- **Втрата доступу.** Якщо папку видалили, перейменували так, що bookmark не відновлюється, або доступ відкликано, у секції з'являється попередження і кнопка «Вибрати папку знову». Якщо папку перемістили, а bookmark ще відновлюється (`isStale`), він тихо оновлюється.
- **Вимкнення** забуває папку. Файли в ній лишаються.

## Ручні дії

- **«Експортувати зараз»** відкриває `.fileExporter` з ім'ям `Saifu-backup-YYYY-MM-DD-HHmm`. Файл можна зберегти будь-куди у «Файлах». Якщо його збережено в контейнер застосунку, замість «Копію експортовано» з'являється попередження, що папка видаляється разом із застосунком.
- **«Імпортувати»** відкриває `.fileImporter` для JSON, далі працює як описано в розділі «Імпорт і перевірка».
- Під секцією показується «Остання копія: …» — час останнього запису `Saifu-latest.json`. Ручний експорт цей час не змінює.

## Компоненти

| Тип | Файл | Роль |
|---|---|---|
| `BackupFileDTO` та інші DTO | `Saifu/Backup/BackupDTO.swift` | Формат файлу, мапінг домен ↔ DTO з перевіркою |
| `BackupService`, `JSONBackupService`, `BackupDate` | `Saifu/Backup/BackupService.swift` | Експорт, відбиток, перевірка, відновлення через `WalletRepository` |
| `BackupFolderAccess`, `BookmarkBackupFolder`, `BackupFileName` | `Saifu/Backup/BackupFolder.swift` | Bookmark у `UserDefaults`, запис latest і щоденних знімків, ротація (поза головним потоком) |
| `ChangeNotifyingWalletRepository` | `Saifu/Repositories/ChangeNotifyingWalletRepository.swift` | Декоратор репозиторію: повідомляє про кожну зміну даних |
| `BackupDocument` | `Saifu/Backup/BackupDocument.swift` | `FileDocument` для `.fileExporter` |
| `BackupError` | `Saifu/Backup/BackupError.swift` | Помилки й тексти для користувача |
| `BackupViewModel` | `Saifu/ViewModels/BackupViewModel.swift` | Стан секції, дебаунс і черга записів автокопії, імпорт з копією перед заміною |

`SettingsView` лише показує стан і викликає `BackupViewModel`. Конкретні `JSONBackupService` і `BookmarkBackupFolder` створюються в композиційному корені (`SaifuApp` / `ScreenFactory`).

Щоб Documents застосунку було видно у «Файлах», додано ключі Info.plist: `LSSupportsOpeningDocumentsInPlace` (налаштування збірки) і `UIFileSharingEnabled` (`Saifu-Info.plist`, який Xcode зливає зі згенерованим Info.plist). Це ключі Info.plist, а не capabilities.

## Покрокова перевірка (симулятор)

1. Створити гаманець, додати витрати й поповнення, звірити.
2. **Експорт:** «Експортувати зараз» → «На iPhone» → зберегти. Під секцією з'являються «Копію експортовано» і дата.
3. **Імпорт:** видалити гаманець або додати витрату → «Імпортувати» → вибрати файл → «Замінити». Дані й порядок гаманців повертаються на всіх вкладках, повідомлення каже, куди збережено попередні дані (`Saifu-before-import-…json`).
4. **Пошкоджений файл:** у «Файлах» обрізати JSON або змінити `"formatVersion" : 1` на `99` (чи просто імпортувати будь-який інший JSON). З'являється зрозуміла помилка, підтвердження не показується, дані без змін.
5. **Автокопія:** увімкнути тумблер → вибрати папку. З'являються `Saifu-latest.json` і `Saifu-backup-<сьогодні>.json`.
   - Додати витрату → приблизно через 3 с `Saifu-latest.json` оновлюється (час зміни у «Файлах» → «Інфо», нова витрата в JSON), а «Остання копія» в налаштуваннях показує новий час.
   - Додати три витрати поспіль (менш ніж за 3 с між ними) → один запис через ~3 с після останньої.
   - Додати витрату й одразу натиснути Home → файл оновлюється одразу, без очікування дебаунсу.
   - Щоденний знімок за сьогодні після першого запису більше не змінюється.
6. **Ротація:** покласти в папку 9 файлів `Saifu-backup-2026-01-0X.json` і будь-який `Saifu-backup-2020-01-01-1200.json`, вимкнути й знову увімкнути автокопію з цією папкою. Лишається 7 щоденних знімків (сьогоднішній і 6 найновіших), ручний експорт на місці.
7. **Папка в контейнері:** увімкнути автокопію й вибрати «На iPhone → Saifu» (або вкладену папку). Папку відхилено з повідомленням, тумблер вимикається. Експорт у «На iPhone → Saifu» дає попередження, хоча файл зберігається.
8. **Втрата доступу:** видалити папку у «Файлах» → змінити дані й зачекати 3 с. Секція показує попередження й «Вибрати папку знову».

### Результат перевірки на симуляторі (iPhone 13 Pro, iOS 27.2)

Тимчасовий Debug-сценарій (не в репозиторії) додавав витрати через ту саму `AddExpenseViewModel`, що й форма на головній, а зовнішній скрипт кожні 50–100 мс читав час зміни й вміст `Saifu-latest.json`. Час — у секундах від вибору папки:

| Подія | Запис `Saifu-latest.json` |
|---|---|
| 0,00 папку обрано | 0,02 (5 витрат) |
| 6,11 витрата | 9,30 (6 витрат), через 3,2 с |
| 15,55 / 16,30 / 17,01 три витрати | 20,23 (9 витрат), один запис |
| 26,55 `dataChanged()` без зміни даних | запису немає (відбиток той самий) |
| окремий запуск: 4,07 витрата → 5,17 застосунок у фоні | 5,30 (одразу, без очікування 3 с) |

Щоденний знімок за день створено один раз. Ротація з 9 старими знімками лишила 7, а ручний експорт і сторонній файл не зачепила.
